## About LoCoMo

LoCoMo (Long Conversation Memory) tests long-term conversational memory across multiple question types:

- **Single-hop:** direct recall of a single fact
- **Multi-hop:** combining two or more facts
- **Temporal:** questions about when events happened
- **Open-ended:** questions with looser answer boundaries

The standard result here uses 10 conversations and the 1,540 category 1-4 questions reported in the paper/logs.

## What changed from older runs

Older run labels such as Run F and Run H are historical. The active LoCoMo number is the Phase 5 v0.5 tuned-default run, not the earlier conv-0 rerank pilot or the May current-refresh baseline.

The old conv-0 rerank pilot remains useful as an ablation signal, but it should not be cited as a full benchmark result.

## What we learned

### Temporal lifecycle recall is the sharpest in-house signal

The relabelled current-refresh artifact shows the clearest in-house gap on temporal questions: Cognitive Memory 48.5% F1 versus NaiveRAG 20.5% F1 under the same harness and answer model. That is the strongest LoCoMo evidence for lifecycle machinery: validity, decay-aware ranking, reinforcement, and deep recall.

Multi-hop remains important, but the later NaiveRAG comparison made the claim narrower. NaiveRAG was competitive or better on some direct lookup categories, so multi-hop should not be used as blanket proof that the full architecture beats vector retrieval everywhere.

### Retrieval is still the bottleneck

The oracle evidence condition is much higher than the current end-to-end score. That means the architecture helps, but better retrieval and answer use are still major improvement areas.

### Temporal questions need a separate adoption gate

Temporal questions require event time, validity status, and ordered evidence, not just semantic recall with timestamps attached. Phase 14 added [temporal reconstruction](/cognitive-memory/concepts/temporal-reconstruction/) as a default-off retrieval path and tested it in a paired A/B. The held-out gain was small and uncertain (+0.75pp mean delta, confidence interval crossing zero), so `temporal_query_mode` stayed off by default.

One correction matters for reading older notes: Phase 14 fixed the LoCoMo category mapping (`1=multi-hop`, `2=temporal`, `3=open-domain`, `4=single-hop`, `5=adversarial`). Pre-correction "temporal is weakest" claims should be treated as historical unless the table was recomputed with that mapping.

## Methodology

All current LoCoMo results use:

- 10 conversations
- 1,540 category 1-4 QA items
- `gpt-4o-mini` for extraction and answering
- `text-embedding-3-small` embeddings
- GPT-4o judge
- current SDK scoring: `sim(m,q) * R(m)^alpha`, default `alpha=0.3`
- v0.5 tuned defaults: associative boost `0.05`, semantic decay `240` days, core-session threshold `2`

See [Methodology](/cognitive-memory/benchmarks/methodology/) for the pipeline and [experimentlog.md](https://github.com/planetaryescape/cognitive-memory/blob/main/cognitive-memory-benchmarks/experimentlog.md) for logged artifacts.
